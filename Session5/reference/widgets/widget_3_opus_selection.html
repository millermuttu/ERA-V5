OPUS: Dynamic Per-Iteration Selection

The 2026 shift is from static filtering to per-iteration selection. Every step, a fresh set of candidate batches arrives; OPUS scores each one by projecting its optimizer-induced update onto a stable proxy direction and keeps only the most useful. But a global English-heavy proxy starves the scarce Indic and agentic data. Watch it happen, then flip the protected Always-On lane and watch it recover.

OPUS = Optimizer-induced Projected Utility Selection. It scores in the optimizer-induced update space, not the raw gradient, using a ghost + CountSketch low-rank approximation, and samples with a Boltzmann rule so the kept set stays diverse.
V4 reality

V4 ran production OPUS keeping ~40% of candidates for ~6× effective tokens (~200B → ~1.2T). But its proxy was English-heavy (cosine 0.876 with the English web band), so it under-valued Indic. That is why Always-On injects 8% of every batch invisible to OPUS.
