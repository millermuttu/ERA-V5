Why padding is worse than absence

Translationese speaks Indic but thinks in English.

Register

Machine-translated text carries English syntax, calques and collocations. It teaches the model to produce stilted Indic — the opposite of fluency.

Worldview

Translated Wikipedia doesn't reason in lakh/crore, ₹, or Indian legal & exam framing. More Tier-D means a model that speaks Indic, thinks American — leaking out the exact thing "India-first" exists to keep in.

Collapse risk

Synthesize on top of translated text and you get recursive translationese amplification. Provenance must be a graph — synthetic may never seed synthetic.

Data · stage 2 / 3 — post-training (SFT)

Teach the model to use what it knows.

~2–5M high-quality examples. The mix is chosen to hit the three headline objectives — coding, agentic, Indic — directly.

Agentic traces

Multi-step tool & function calls with real schemas, multi-file code edits, debugging loops, terminal & browser transcripts. The core of the agentic objective.

Code instruction

Repo-level, test-driven tasks — not single-function HumanEval snippets. Keep the natural-language↔code interleaving.

Verified reasoning

Long math / science chain-of-thought, checked before inclusion. Distilled or self-generated, then filtered by a verifier.

Indic instruction

Native-authored where possible; translated-then-verified otherwise. IndicAlign as a noisy starting point, not the endpoint.

India-grounded tasks

Indian legal Q&A, UPSC / JEE / NEET items, civic & government-service queries, and explicit code-switching handling.

Dialogue & refusals

Multi-turn conversation, format-following, and safety refusals authored in-language — not just English.

Data · stage 3 / 3 — RL / alignment

RLVR for capability. Indian raters for the worldview.

Verifiable rewards (RLVR)

Where most real capability gain now lives — objective and cheap to scale.

Code → unit tests in a sandbox. Math → answer-checkers. Agentic → task-success in a live environment. No human labels needed for the reward.

Preference — worldview & safety

RLHF / DPO with Indian raters for the subjective axes.

Tone, cultural appropriateness, code-switch fluency, refusing India-illegal content correctly. Red-team preference data authored in Indic and romanized forms.

The quiet failure

Preference data collected by non-Indian raters will silently de-Indianize the model — the alignment-stage analog of translationese.

Cleaning — objective-aware

Code isn't cleaned like Malayalam prose.

A universal spine every source passes through, then per-objective lanes.

1 · Dedup

MinHash / LSH, exact + fuzzy. Indic drops the most here — republished news.

2 · PII scrub

Strip personal & sensitive data before anything else touches it.

3 · Decontaminate

Remove eval n-gram overlap early, and log it — or the numbers are fiction.

4 · Provenance tag

Every doc labelled A/B/C/D. The tag drives all downstream weighting.

Indic lane

Language ID across 22 scripts + romanized; NFC matra normalization; per-language KenLM perplexity (80th-pct, nudged up for low-resource). A global threshold deletes low-resource languages.

Code lane

Permissive-license filter, secret removal, file + repo dedup, and a parse / compile / lint quality gate.

Math lane

Verify final answers where checkable, keep step structure, split digits one-per-token.

Translationese

Native-vs-translation perplexity ratio + back-translation consistency → downweight Tiers B/C/D.

Why not 128K

Forces Dravidian back toward 3+ tok/word — kills the population-scale inference economics this project exists for.

Embedding cost

At d_model ≈ 6144, 256K ≈ 1.6B tied / 3.1B untied params — ~4–8% of a 40B model. The right ceiling; higher under-trains rare tokens.

As decisive as the size: train the tokenizer on an Indic-upsampled corpus, with digit-splitting, indentation-preserving pretokenization, and NFC normalization.

The fix · grow the real number

India's native signal lives in audio.

Text crawl won't move it. ASR of Indian video, podcasts, TV/radio, parliamentary & court proceedings, and lectures produces genuinely native, colloquial text no translation can give.

Conservatively 100–200B clean native tokens — 2–3× the entire verified pool, and a moat non-Indian labs won't build.

① ASR — the hero

Indic ASR (AI4Bharat's IndicVoices line) is good enough to transcribe at scale. Highest ROI, hardest to replicate.

② Licensing

News archives, publishers, book digitization — tens of billions of high-register Tier-A tokens.

③ Native-generation

Unbounded, but only as good as its native seed. Weight all acquisition by tier — every clean billion moves Punjabi / Odia the most.

Synthetic doctrine

Three rules that stop the corpus rotting.

01

Provenance is a graph, not a tag

Synthetic may never be seeded from synthetic. No Tier-D feeding Tier-C. This prevents recursive translationese amplification and model collapse.

02

Native-generation over translation, always

Prompt for original, grounded Indic. Never machine-translate a sentence and call it data — translation keeps neither the syntax nor the worldview.

03

Translationese is a filter and an eval

Filter with a native-vs-translation perplexity ratio + back-translation consistency. Then measure whether the trained model itself emits it — in Bharat-eval.

Carry-overs: fit the tokenizer & measure all fertility on native-only text · collect preference/alignment data with Indian raters.

The reframe, in one line

~100B real native tokens, grown mainly through ASR; scale bought through native-generation, not translation; India-first delivered through clean India-knowledge + Indian-rater alignment — on a 256K tokenizer tuned to native fertility.
