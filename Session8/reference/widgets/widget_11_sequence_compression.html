ERA V5 Session 8 · Sequence compression

Store fewer positions. Read fewer summaries.

Long context has many token positions. This design first combines nearby tokens into block summaries, then sends expensive attention only to the summaries most relevant to the current query.

Larger blocks mean fewer stored positions, but each summary must represent more token detail.

Top-k keeps the strongest candidates. The other summaries remain stored but are not read by expensive attention.

The two savings do different jobs: compression changes how much history is stored; top-k changes how much of that compressed history is read for one query.
Where does top-k come from? A small low-rank indexer scores all block summaries cheaply. Its only job is ranking candidates; it does not produce the final attention output.
The trade-off: a block summary can lose token-level detail, and an approximate indexer can miss a useful block. This visual demonstrates the scaling idea, not model quality or DeepSeek-V4’s reported production ratios.
