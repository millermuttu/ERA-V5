## Why

ERA V5 Session 6 requires proving that the training-data contracts defined in Sessions 1-5 (tokenizer, source admission, mixture/curriculum) actually operate as a working system, not just a plan. The assignment (`Session6/reference/session6-lesson.txt` §16) asks for a small but complete Training Data Execution System: documents -> tokenized shards -> manifests -> mixture schedule -> packing -> batches -> training -> consumption ledger -> learning ledger -> checkpoint -> crash -> resume -> replay -> audit. Grading (1000 pts) checks that the pipeline is correct, reproducible, and auditable at toy scale, and that evidence of each invariant is generated by the code itself, not hardcoded.

## What Changes

- Add a toy-scale, deterministic training-data execution pipeline under `Session6/pipeline/`: corpus generation, tokenizer freezing, content-addressed immutable shards, shard manifests with an admission gate, an eval/validation firewall, mixture-schedule compilation with protected floors, OPUS-style admission decisions (accepted/rejected/deferred/protected), multiple packing policies with correct loss/attention masks and position ids, a training loop that writes consumption and learning ledgers, checkpoints bound to ledger offsets, deliberate crash + resume verification, ledger-mode replay with hash verification, fork-from-checkpoint, and throughput/packing-efficiency reporting.
- Add a single-command orchestrator `Session6/run_demo.py` that runs the full pipeline end-to-end and generates the required `submission_artifacts/` tree (`run.log`, `evidence.json`, `evidence.md`, `manifests/`, `ledgers/`, `checkpoints/`, `performance.json`), where the evidence bundle is computed from the actually-generated artifacts.
- Add a pytest suite under `Session6/pipeline/tests/` covering the invariants the rubric grades: admission scoring, firewall gates, protected-floor compliance, packing/mask correctness, ledger monotonicity, crash/resume no-skip-no-repeat, replay hash equality, and throughput recomputability.
- Add a `Session6/README.md` documenting the architecture, design decisions, and exact reproduce commands, following the pattern established in `Session4/README.md`.

## Impact

- New directory tree: `Session6/pipeline/` (17 modules + `tests/`), `Session6/run_demo.py`, `Session6/README.md`.
- Generated, gitignored output: `Session6/submission_artifacts/` (manifests, ledgers, checkpoints, run.log, evidence.json/md, performance.json) - recreated fresh by every `run_demo.py` invocation.
- No changes to Session1-5 code or existing pipelines; Session6 reuses only the mixture lane percentages established in `Session5/submission.md` as reference defaults.
- Dependencies: stdlib only (hashlib, json, dataclasses, re) - no new third-party packages.
